Type that fits

Two typefaces, one rhythm

A design system pairs a display face with a text face and asks them to behave as one. They rarely do. The same nominal size renders smaller in one than the other, the same nominal weight renders lighter, and neither lands on the grid the layout is built on.

The usual answer is to eyeball it: nudge the heading size until it looks right, pick a heavier weight until it stops looking thin, and accept that the baselines drift. That works for one screen, in one browser, at one size. It stops working the moment the scale changes.

The alternative is to measure. Every mismatch on this page has a number behind it — an x-height ratio read from the font file, a stem width read from the outline, a cap height the browser reports — and every fix below is that number, applied. Nothing is typed in.

What the toggles show

Each control on the right is a request a designer or developer would type to an agent. The panel underneath shows the CSS that request produces, and the text on the left shows what it does. Switch the heading face first: that is the problem. Then apply the fixes in order.

The x-height correction is derived from the two font files, not from a specification page. The weight is matched by measured stem width, not by the number in the font's name. The scale is one base and one ratio, snapped to half a pixel. The line-heights are a curve, snapped to four. The baseline grid is what all of that was for.

When the last toggle is on, every line of text on this page sits on the same four-pixel grid, in both typefaces, and the code that does it fits on a slide.
